#+TITLE: OpenCode.el V2 TODO

* Current state

The package now targets the OpenCode V2 HTTP API:

- V2 service discovery via =~/.local/state/opencode/service.json=.
- V2 endpoints under =/api=, including prompts, sessions, agents, models,
  MCP, permissions, forms, fork, compact, revert, and interrupt.
- V2 flat SSE events under =/api/event=.
- V2 message/content normalization in =opencode-v2.el=.
- V2 forms are handled by the question/form UI.

Known limitations of the first V2 port:

- Session sharing is not exposed by the V2 HTTP API; the share/unshare
  commands now signal an error.
- Deleting one message is not exposed by the V2 HTTP API; use revert or
  fork instead.
- LSP is not provided by the V2 server (see below).
- The session control buffer fetches at most 50 sessions.
- Message replay fetches at most 200 messages per session.
- File edit hooks have no line ranges from V2 tool results.
- The control buffer uses =vtable=; check behavior in frame-less daemons.

* TODO Split the code into smaller modules

The largest files are still too large:

- =opencode-sessions.el= (~1,450 lines)
- =opencode.el= (~1,050 lines)
- =opencode-question.el= (~560 lines)

Suggested split, targeting under ~400 lines per file:

- [ ] =opencode-api.el=: transport only (HTTP, auth, envelopes, pagination).
- [ ] =opencode-v2.el=: V2 normalization (messages, sessions, models, tools).
- [ ] =opencode-events.el=: event parsing and event-to-UI dispatch.
- [ ] =opencode-session.el=: session lifecycle, open/replay, status.
- [ ] =opencode-render.el=: comint output, Markdown, margins, tables, diffs.
- [ ] =opencode-prompt.el=: prompt input, attachments, slash commands, shell.
- [ ] =opencode-control.el=: session control buffer and vtable.
- [ ] =opencode-model.el=: providers, models, agents, variants.
- [ ] =opencode-permission.el=: keep permission UI, move event mapping out.
- [ ] =opencode-form.el=: extract V2 forms from =opencode-question.el=.
- [ ] =opencode-compat.el=: small V1-shaped compatibility helpers, if needed.
- [ ] Keep public autoloads in =opencode.el= only.

Acceptance criteria:

- [ ] No file over ~500 lines except tests and generated data.
- [ ] No behavior changes while splitting; ERT stays green.
- [ ] Every module has a clear "requires" direction and no UI/API cycles.

* TODO LSP in OpenCode V2

Facts from the V2 documentation:

- V2 accepts and preserves =lsp= config for compatibility, but it does not
  run language servers, expose LSP tools, or produce LSP diagnostics.
- The V1 =/lsp= endpoint no longer exists; polling it only produces errors.

Recommendation:

- [ ] Do not try to restore server-side LSP through the V2 HTTP API.
- [ ] Use Emacs' own LSP clients (=eglot= or =lsp-mode=) for editing.
- [ ] Feed diagnostics back to the model after edits:
  - run =eglot= / =flycheck= / =flymake= after =opencode-file-edited-functions=;
  - report results through =opencode-report-diagnostic=;
  - keep the existing finished-editing hook contract.
- [ ] If V1 support is ever kept, gate LSP polling behind a server-version check.
- [ ] Document that the old OpenCode LSP status indicator is intentionally gone.
