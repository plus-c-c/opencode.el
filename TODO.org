#+TITLE: OpenCode.el V2 TODO

* Current state

The package now targets the OpenCode V2 HTTP API:

- V2 service discovery via =~/.local/state/opencode/service.json=.
- V2 endpoints under =/api=, including prompts, sessions, agents, models,
  MCP, permissions, forms, fork, compact, revert, and interrupt.
- V2 flat SSE events under =/api/event=.
- V2 message/content normalization in =opencode-v2.el=.
- V2 forms are handled by the question/form UI.

Known limitations:

- Session sharing is not exposed by the V2 HTTP API; the share/unshare
  commands now signal an error.
- Deleting one message is not exposed by the V2 HTTP API; use revert or
  fork instead.
- LSP is not provided by the V2 server (see below).
- The session control buffer fetches at most 50 sessions and provides a
  separate search command for older sessions.
- Message replay fetches the newest 200 messages per session; full cursor
  pagination remains optional.
- File edit hooks use line ranges when V2 tool metadata supplies a diff.
- The control buffer uses =vtable=; it is intended for normal GUI frames.

* Completed: split the code into smaller modules

All implementation files are now below ~500 lines (tests and generated
data excluded).  The split is:

- [x] =opencode-api.el=: transport only (HTTP, auth, envelopes, pagination).
- [x] =opencode-v2.el=: V2 normalization (messages, sessions, models, tools).
- [x] =opencode-events.el=: event parsing and event-to-UI dispatch.
- [x] =opencode-sessions.el= + =opencode-session-actions.el=: session lifecycle, open/replay, status.
- [x] =opencode-render.el=: comint output, Markdown, margins, tables, diffs.
- [x] =opencode-prompt.el=: prompt input, attachments, skills, slash commands, shell.
- [x] =opencode-control.el=: session control buffer and vtable.
- [x] =opencode-model.el=: providers, models, agents, variants.
- [x] =opencode-permission.el=: keep permission UI; event mapping lives in =opencode-events.el=.
- [x] =opencode-form.el=: V2 forms extracted from =opencode-question.el=.
- [x] =opencode-compat.el=: not needed; V2 normalizers provide the compatibility layer.
- [x] Keep public entry points in =opencode.el= and small feature modules.

Acceptance criteria:

- [x] No file over ~500 lines except tests and generated data.
- [x] No behavior changes while splitting; ERT stays green.
- [x] Every module has a clear "requires" direction and no UI/API cycles.

* Completed: LSP guidance in OpenCode V2

Facts from the V2 documentation:

- V2 accepts and preserves =lsp= config for compatibility, but it does not
  run language servers, expose LSP tools, or produce LSP diagnostics.
- The V1 =/lsp= endpoint no longer exists; polling it only produces errors.

Recommendation:

- [x] Do not try to restore server-side LSP through the V2 HTTP API.
- [x] Use Emacs' own LSP clients (=eglot= or =lsp-mode=) for editing.
- [x] Feed Flycheck and Flymake/Eglot diagnostics back to the model after edits:
  - run =eglot= / =flycheck= / =flymake= after =opencode-file-edited-functions=;
  - report results through =opencode-report-diagnostic=;
  - keep the existing finished-editing hook contract.
- [x] Old V1 LSP polling removed; no server LSP is attempted.
- [x] Document that the old OpenCode LSP status indicator is intentionally gone.
